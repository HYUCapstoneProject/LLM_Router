# 통일 평가 시제품 — 2026-10-13

실험 코드: **EV-05** · [실험 목록](../../REGISTRY.md)

[라우터 평가 계획서](../../../docs/ml/ROUTER_EVALUATION_V2_PLAN.md) 3절의 어댑터와 결정 규칙이 실제로 작동하는지 확인한 시제품이다. 새 학습·추론은 없다. R0·R1의 기존 8192 점수(D_dev·봉인 test)를 사용했다.

## 방법

1. **채점:** D_dev와 test 모두 v2 정정을 적용했다. RouterBench 제외 문항은 뺐다.
2. **어댑터:** R0는 난이도 확률에 train의 "라벨별 단계 성공률" 표(v2)를 곱했고, R1은 sigmoid를 썼다. 그다음 둘 다 D_dev에서 단계별 isotonic 보정으로 단계별 성공 확률을 만들었다.
3. **실패 상관:** 단계 간 실패 상관 ρ를 D_dev에서 추정했다(RouterBench .476, xRouteBench .814). ρ = 1은 "위 단계가 실패하면 아래 단계도 실패", ρ = 0은 독립이다.
4. **결정 규칙:**
   - 한 번에 고르기: argmax [p̂ − λ ĉ]
   - 상향 고려: 시작 단계마다 기대 해결 − λ × 기대 비용 − κ × 기대 실패 횟수를 계산해 가장 큰 단계를 고른다
5. **평가:** test에서 기록된 결과로 상향을 시뮬레이션하고, 효용 = 최종 해결 − λ × 총비용 − κ × 실패한 시도 수를 계산했다. 총비용은 원천별 "전부 high"의 평균 비용을 1로 둔다.

## 결과

[utility-grid.csv](utility-grid.csv)에 λ ∈ {.05, .2, .5} × κ ∈ {0, .05, .15, .4}의 모든 정책 값(첫 시도 성공, 최종 해결, 비용, 실패 횟수, 효용)이 있다. 요약은 계획서 3.3절에 있다.

- 어댑터를 거치면 R0와 R1의 효용이 거의 같다.
- 상향 고려 규칙은 각 κ에서 가장 좋은 고정 시작 단계와 같거나 조금 낫다.
- κ를 모르는 "한 번에 고르기"는 비용을 과하게 쓴다.

## 한계

- 보정과 선택은 D_dev, 평가는 이미 여러 번 관찰한 봉인 test다. 연구용 시제품이며 판정 근거가 아니다(판정은 계획서 E2에서 한다).
- 실패 상관은 단계 쌍마다 하나의 ρ로 근사했다.
