# F5 라벨 비율을 맞춘 오류 교정 재학습 결과 — 2026-10-10

[계획서 15절](../../../docs/ml/RETRAINING_EFFECT_EXPERIMENT.md)의 F5를 개인 Colab T4에서 실행한 결과다. F4의 오답(운영 1.0이 원래 난이도 라벨과 다르게 예측한 질문)을 전부 쓰되, window마다 맞게 예측한 질문을 라벨별로 더해 실제 라벨 비율을 되돌리고, 복습도 실제 비율대로 뽑았다(seed 42/43/44, 6회 재학습). 최종 평가는 봉인 test 7,202문항과 RouterArena 8,379문항, 8192 토큰이다. F4 run의 최종 예측을 해시 검증 후 불러와 같은 문항에서 비교했다. 라벨과 라우팅 결과는 v1 채점 기준이다.

## 1. 결론

1. **F4의 쏠림 원인은 학습 데이터의 라벨 비율이었다.** 비율만 맞추자 판단 쏠림이 사라졌다. F5−F4 정확도는 test +.302 [+.285, +.317], RouterArena +.200 [+.188, +.213]이다.
2. **그러나 초기 R0(F0)보다 나아지지 않았다.** 원래 라벨 정확도는 test .619→.580(−.039 [−.049, −.030]), RouterArena .454→.444(−.010 [−.018, −.002])로 조금 낮다. hard 재현율은 .276→.146으로 떨어졌다. seed 세 개가 거의 같다(test .576~.585).
3. **라우팅은 원천별로 엇갈렸다.** RouterBench는 첫 시도 품질 +.035에 상대 비용 +.028, xRouteBench는 상대 비용 −.082에 품질 −.006이다. 두 원천 모두 "항상 medium"보다 아래이고, 최종 해결률은 F0와 같다.
4. **해석:** 비율을 지키면 같은 분포의 정답 문항을 약 4천 개 더 학습하는 것과 같고, 텍스트로 알 수 있는 정보의 한계를 넘지 못한다. 성능이 멈추는 경계는 [천장 분석](../routing-ceiling-20261013/REPORT.md)에 정리했다.
