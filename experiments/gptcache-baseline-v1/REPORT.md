계획: [PLAN.md](PLAN.md) (해시 `FREEZE.json`). 코드: `make_inputs.py`, `cloud/run_gptcache.py`, `evaluate.py`.

## 실행 환경과 시행착오

`gptcache==0.1.44`, onnxruntime 1.31.0, faiss-cpu 1.15.1, transformers 4.57.6, sentence-transformers 5.7.0, numpy 1.26.4.
같은 입력으로 네 번 실패하고 다섯 번째에 정상 실행됐다. 실패 원인은 모두 환경·설정이며 입력과 평가 규칙은 바꾸지 않았다.

| 빌드 | 결과 | 원인 / 조치 |
|---|---|---|
| 68ee7861 | 설치 실패 | Python 3.10 이미지에서 torch 빌드 의존성 없음 → 3.11 이미지 |
| 73a7d3d6 | import 실패 | onnxruntime 1.16.3 실행 스택 오류 → 1.2x 이상 |

| c8e8c20d | 정상 | 저장 오류 0, faiss 개수 = 항목 수, 조회 예외 0 |

점수 수집(기준 0) 실행으로 다시 낸 0.8 판정은 세 설정 모두 실제 0.8 실행과 1,500건 전부 일치했다.

## 결과 (test, 같은 뜻 재사용 / 함정 통과)

대화형 test 같은 뜻 384·함정 192, D2 재현본 test 200·200. 대괄호는 95% 구간.

| 설정 | 기준 | 대화형 | D2 재현본 |
|---|---|---:|---:|
| G1 GPTCache 기본 (임베딩 거리) | 0.8 (기본) | 90.6% [87, 93] / **82.8%** [77, 88] | 99.5% / **100%** |
| G1 | 맞춤 (0.9994) | 0.0% / 0.0% | 0.0% / 14.0% |
| G2 quora 리랭커 | 0.8 (기본) | 38.5% [34, 44] / 8.9% [5, 14] | 67.5% [61, 74] / 29.0% [23, 36] |
| G2 | 맞춤 (0.955) | 25.3% / 3.1% | 29.5% / 6.5% |
| G3 ALBERT 중복질문 분류기 | 0.8 (기본) | 29.9% / 10.4% | 82.5% / 61.0% |
| G3 | 맞춤 (0.976) | 6.8% / 1.0% | 14.0% / 11.0% |

- "맞춤"은 두 데이터의 calibration을 합쳐 함정 통과 ≤ 5%에서 같은 뜻 재사용이 최대인 기준이다(정규화 점수 0~1).
  데이터셋별로 따로 맞춰도 결론은 같다(`evaluation.json`의 `tuned_per_dataset`).
- 같은 뜻 질문이 다른 원질문에 재사용된 경우: G1 기본에서 대화형 0.5%, D2 0.5%. 나머지 0.
- GPTCache 기본 기준 0.8은 이 라이브러리의 거리 환산(정규화 벡터의 L2² 거리, 최대 4)에서 코사인 0.6 이상에 해당한다.
  기본 후보 수는 1개(top_k=1)다.

## 우리 방식과 비교

| 방식 | 대화형 | D2 재현본 |
|---|---:|---:|
| GPTCache 기본 (G1) | 90.6% / 82.8% | 99.5% / 100% |
| GPTCache + quora 리랭커 (G2, 기본) | 38.5% / 8.9% | 67.5% / 29.0% |
| GPTCache + quora 리랭커 (G2, 맞춤) | 25.3% / 3.1% | 29.5% / 6.5% |
| 우리 운영 C3 (BGE + quora AND) | 49.5% / 12.5% | 90.0% / 69.0% |
| **우리 NLI (deberta-base-long-nli + 차이 문장, 기준 하나)** | **84.1% / 4.7%** | **95.5% / 1.0%** |

우리 NLI 결과는 `nli-diff-v1`과 같은 test 분할·같은 선택 규칙(합친 calibration, 함정 ≤ 5%)이다.

- GPTCache 기본은 함정을 83~100% 통과시킨다. 기준을 올려 함정을 막으면 같은 뜻 재사용이 0%가 된다. 이 임베딩(ALBERT
  small)에서는 같은 뜻과 함정의 거리 분포가 거의 겹친다.
- GPTCache의 판정 모델 두 가지(quora, ALBERT 분류기)는 함정 ≤ 5%를 지키는 기준에서 같은 뜻 재사용이 7~30%다.
- 우리 NLI 방식만 두 데이터 모두에서 함정 ≤ 5%와 같은 뜻 재사용 84% 이상을 함께 낸다.

## 지연 (참고)

Cloud Build(32 vCPU)에서 조회 한 번 평균(임베딩 포함): G1 116~142ms, G2 33~58ms, G3 25~77ms. G2·G3는 G1과 같은 임베딩을
재사용해(같은 실행 안에서 메모) 임베딩 시간이 빠진 값이다. 운영 VM(2 vCPU) 값이 아니라 우리 방식의 운영 추정치와 직접 비교하지
않는다.

## 한계

- 데이터는 Claude가 작성했다. 대화형은 모두 99자 이하이고, 두 데이터 모두 함정 비중이 높다(33%, 50%).
- GPTCache 0.1.44는 2024년 이후 갱신이 없고, 최신 transformers와 호환되지 않는다.
- 바꾼 GPTCache 기본값은 퇴출 크기 하나다. 다른 임베딩(OpenAI, SBERT 등)이나 top_k를 바꾼 설정은 재지 않았다.
