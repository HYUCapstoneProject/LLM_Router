# NLI 도입 방식 비교 결과 (2026-10-11)

계획: [PLAN.md](PLAN.md). 코드: `compare.py`(계획 그대로), `posthoc.py`(사후 분석). 결과: `results/comparison.json`, `results/posthoc.json`.
새 채점은 없고 `cache-natural-v1`, `d2-replica-v1`에서 계산한 점수를 다시 썼다.

## 1. 계획대로 비교한 결과 (test, 함정 통과 ≤ 5%로 calibration 선택)

대화형 test: 같은 뜻 384, 함정 192. D2 재현본 test: 같은 뜻 200, 함정 200. 값은 같은 뜻 재사용 / 함정 통과.

| 방식 | 모델 | 기준 | 대화형 | D2 재현본 |
|---|---|---|---:|---:|
| 운영 C3 (참고) | quora | 코사인 0.8774 AND 0.0358 | 49.5% / 12.5% | 90.0% / 69.0% |
| A 기준 하나 | base, 1위만 | 0.9946 | 19.3% / 0.5% | 75.0% / 9.0% |
| A 기준 하나 | xsmall, 1위만 | 0.9893 | 4.4% / 0.0% | 57.0% / 12.0% |
| **B 길이별 기준** | **base, 1위만** | **L=200자, 짧음 0.0188, 김 0.9966** | **72.7% / 4.7%** | **53.5% / 3.0%** |
| B 길이별 기준 | xsmall, 1위만 | L=270자, 0.0542 / 0.9930 | 72.1% / 5.7% | 55.5% / 8.0% |
| C 짧은 질문만 NLI | base, 1위만 | L=660자, 0.8084 | 53.4% / 2.1% | 77.0% / 9.5% |
| 참고: 데이터셋별 따로 | base, 1위만 | 0.0269 / 0.9964 | 69.0% / 4.2% | 46.0% / 3.5% |

- 같은 뜻 질문이 다른 원질문에 재사용된 경우는 모든 NLI 방식에서 0~1%였다.
- A(기준 하나)는 두 데이터를 함께 만족시키지 못한다. 긴 문항에 맞춰 기준이 0.99대로 올라가 대화형 재사용이 무너진다.
- B(base)가 두 데이터 모두에서 함정 5% 이하를 지키며 재사용이 가장 높다. 데이터셋을 알고 따로 고른 "참고"보다도
  D2 재사용이 높은데, D2 안의 짧은 문항(200자 이하, test의 15%)이 짧은 쪽 기준으로 잘 처리됐기 때문이다
  (rb_open 85.7% / 0%, rb_math 76.5% / 5.9%).
- C는 계획한 L 선택 규칙이 짧은 구간에 D2 문항을 많이 끌어와 calibration에서는 5%를 맞췄지만 test에서 9.5%로 넘었다.
  후보 전체를 검사한 변형도 결론이 같다(`comparison.json`).

## 2. 사후 분석 (계획 밖)

| 방식 (L=200자, 1위만) | 기준 | 대화형 | D2 재현본 | 지연 추정(짧음 / 김) |
|---|---|---:|---:|---:|
| base 단일 | 0.0188 / 0.9966 | 72.7% / 4.7% | 53.5% / 3.0% | 536ms / 1,398ms |
| **짧음 xsmall + 김 base** | 0.0354 / 0.9966 | **74.7% / 5.7%** | **53.5% / 3.0%** | **185ms** / 1,398ms |
| xsmall 단일 | 0.0354 / 0.9930 | 74.7% / 5.7% | 46.0% / 5.0% | 185ms / 469ms |
| 짧음 base, 김 완전 일치만 | 0.0188 / – | 72.7% / 4.7% | 15.5% / 0.5% | 536ms / 0 |

지연은 `cache-natural-v1` 7절의 운영 VM 추정치(모델 계산분 p50, 1위 후보 양방향)다. 현재 리랭커는 후보 5개 약 244ms.

- 대화형 차이(72.7% / 4.7% 대 74.7% / 5.7%)는 신뢰구간 안이다. 짧은 질문은 xsmall로 충분하다.
- 긴 문항은 base가 낫다(53.5% / 3.0% 대 46.0% / 5.0%). D2 AUC도 base 0.931, xsmall 0.876.
- L 민감도(base): 100~200자에서 결과가 비슷하고, 250자 이상이면 짧은 쪽 기준이 올라가 대화형 재사용이 떨어진다.

| L (base 단일) | 대화형 | D2 재현본 |
|---:|---:|---:|
| 100 | 69.0% / 4.2% | 48.5% / 2.5% |
| 150 | 69.0% / 4.2% | 49.5% / 3.0% |
| 200 | 72.7% / 4.7% | 53.5% / 3.0% |
| 250 | 62.5% / 3.6% | 57.0% / 4.0% |
| 300 | 62.5% / 3.6% | 63.0% / 5.5% |

- 가장 약한 곳은 여전히 긴 지문 + 질문 한 줄 변경 유형이다(xrb_open 21.4% / 7.1%, xrb_mcq 29.4% / 0%).

## 3. 권장

발표용 실험 환경 기준으로 **"200자 경계 길이별 기준 + 코사인 1위 후보만 NLI 검증"**을 권한다.

- 성능 우선: base 단일. 모델 하나라 구현이 가장 단순하다.
- 지연 타협: 짧음 xsmall + 김 base. 대화형 질문 검증이 185ms로 현재(244ms)보다 빠르고 정확도는 같다. 모델 두 개를 올려야 한다.

운영 C3 대비: 대화형은 재사용 49.5% → 72.7~74.7%, 함정 12.5% → 4.7~5.7%. D2 재현본은 함정 69% → 3.0%, 재사용 90% → 53.5%.

## 4. 한계

- 대화형 질문은 모두 99자 이하라, 200자 경계는 사실상 두 데이터셋을 가른다. 100~200자 일반 질문은 D2 재현본의
  짧은 문항(test 61개)으로만 확인됐다.
- 두 데이터 모두 Claude가 작성했고, 길이 경계·기준·모델 조합을 같은 calibration에서 골랐다. 사후 분석(2절)은 test를 본
  뒤의 비교라 낙관적일 수 있다.
- 긴 쪽 기준 0.9966은 점수 차이가 매우 작은 구간이다. 운영 FastAPI 점수가 이 환경과 1e-4 수준으로 일치하는지 반영 후
  다시 확인해야 한다.
- 지연은 추정치다. 운영 VM 실측 전이다.
