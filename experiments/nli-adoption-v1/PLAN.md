# NLI 도입 방식 비교 (2026-10-11, 채점 전 고정)

목적: 발표 보고서용으로 NLI 판정을 어떤 형태로 넣을지 정한다. 새 모델 채점은 하지 않고 이미 계산한 점수만 쓴다.

## 데이터

- 대화형: `cache-natural-v1` (300그룹, 같은 뜻 2 + 함정 1, 운영 검색 후보). 분할은 기존과 같다(`sha256(id)[0] % 3 == 0` → calibration).
- 벤치마크형: `d2-replica-v1` (300그룹, 같은 뜻 1 + 함정 1, 원질문 300 + 배경 4,986 캐시). 분할은 기존 `split`.
- 두 데이터의 calibration을 합쳐 기준을 고르고, 각 test에서 한 번 평가한다.

## 비교 방식

판정 모델은 NLI deberta-v3 base, xsmall 두 가지. 점수는 양방향 함의의 최소값. 후보는 코사인 1위만(주) / 후보 전체(보조).

- A. 기준 하나: 합친 calibration 함정 통과 ≤ 5%에서 같은 뜻 재사용 최대.
- B. 길이별 기준 둘: 질문 글자 수 ≤ L 이면 짧은 쪽 기준, 아니면 긴 쪽 기준. 각 구간 함정 통과 ≤ 5%에서 각각 고르고,
  L(40~800, 10 간격)은 합친 calibration 같은 뜻 재사용 합이 최대인 값. 동률이면 가장 작은 L.
- C. 짧은 질문만 NLI: ≤ L 이면 NLI 기준, 아니면 의미 캐시를 쓰지 않음(완전 일치만). 짧은 구간 함정 ≤ 5%. L 선택은 B와 같다.
- 참고(상한): 데이터셋별로 따로 고른 기준. 운영에서는 데이터셋을 알 수 없으므로 상한으로만 쓴다.
- 참고: 운영 C3(코사인 0.8774 AND quora 0.0358).

## 지표

test에서 데이터셋별 같은 뜻 재사용(자기 원질문), 같은 뜻 오재사용(다른 원질문), 함정 통과, Clopper–Pearson 95%.
지연은 `cache-natural-v1/results/latency_bench.json`의 운영 추정치를 인용한다.

## 알려진 한계 (채점 전 기록)

  받는 경우를 따로 보고한다.
- 두 데이터 모두 Claude가 작성했다.
