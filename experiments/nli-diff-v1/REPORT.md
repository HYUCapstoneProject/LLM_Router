## 3. 해석

- 긴 문항의 문제는 대부분 "같은 지문이 점수를 포화시키는 것"이었다. 바뀐 문장만 비교하면 긴 문항이 짧은 질문 비교로 바뀌어
  기준 하나로 두 데이터를 함께 처리할 수 있다.
- 긴 입력·다과제로 학습한 deberta-base-long-nli는 원문만으로도 기존 모델보다 훨씬 낫고(D2 93.0% / 6.5%), 기준이 0.28~0.29로
  확률답게 나온다. 차이 문장을 더하면 D2 함정이 6.5% → 1.0%로 준다.
- 원문·기준 하나에서 D2 재사용 90% 이상과 함정 6.5% 이하를 함께 낸 모델은 deberta-base-long-nli뿐이다. 나머지는 D2 함정이
  8~14.5%이거나(base, xsmall, MoritzLaurer 둘, ModernBERT), 함정은 낮아도 재사용이 50.5%(small-long-nli)다. 차이 문장을 넣으면
  일곱 모델 모두 D2 함정이 1~6.5%, 재사용이 87.5~97%가 된다. 차이 문장이 모델 선택보다 효과가 크다.
- 차이 문장에서 고른 기준은 대부분 0.03~0.08로 낮다. 확률이 실제 의미와 맞지 않는 문제가 남는다는 뜻이다.
  deberta-base-long-nli(0.28)와 small-long-nli(0.41)만 확률에 가까운 값이 나온다.
- 지연: 차이 문장은 긴 문항을 평균 원문의 18%로 줄이므로, 긴 입력도 짧은 질문과 비슷한 계산량이 된다. base 크기 모델의 짧은
  질문·1위 후보 추정은 536ms, small 크기는 273ms(`cache-natural-v1` 7절, 운영 VM 추정)다.

## 4. 한계

- **D2 재현본의 변형은 문장 하나를 바꾸는 방식으로 만들었다.** 차이 추출이 그 편집을 정확히 잘라내므로 이 방식에 유리하다.
  지문 전체를 다시 쓴 변형이면 공통 문장이 없어 원문 비교로 돌아간다(그때는 원문 결과가 기준).
- 두 데이터 모두 Claude가 작성했다. 대화형은 모두 99자 이하.
- tasksource 모델은 공개 데이터 수백 종으로 학습했다. D2 원문 출처(공개 벤치마크)의 지문을 학습 중에 봤을 수 있다. 편집된 변형과
  라벨은 이번에 새로 만든 것이다.
- 차이 추출은 문장 단위다. 대명사가 앞 문장을 가리키면 맥락이 빠진다.
- 지연은 아직 추정치이고, 새 모델들은 따로 재지 않았다(같은 구조·크기의 deberta-v3 기준).
- MoritzLaurer 두 모델은 가중치가 float16, ModernBERT는 bfloat16으로 저장돼 CPU에서 그대로 돌아 채점이 느렸다(4,300초대,
  1,653초; float32 모델은 181~519초). 운영에 쓰면 float32로 불러야 한다. 이 정밀도에서 낸 점수라 float32와 조금 다를 수 있다.

## 5. 표기 정규화 추가 (v2, 사후)

`reduce_pair(a, b, normalize=True)`: 문장을 맞출 때만 대소문자와 연속 공백을 무시하고, 남기는 문장은 원문 그대로 둔다.
숫자·기호·구두점은 바꾸지 않는다.

- 합성 예시: `"We use Python 3.11.  The list has 120 items."` 대 `"we use python 3.11. The list has 150 items."` →
  v1은 두 문장을 모두 남기고, v2는 `120 items` 대 `150 items` 한 문장만 남긴다.
- 이번 데이터 2,299쌍에서 v2가 v1과 다른 결과를 낸 쌍은 **0개**다. 문장 분할이 이미 앞뒤 공백을 지우고, 재현본 변형은
  부분 문자열 편집이라 대소문자만 다른 공통 문장이 없기 때문이다. 따라서 1~4절의 점수와 결과가 그대로 v2의 결과다.
- `normalize=False`(기본값)는 v1과 같은 출력을 낸다(2,299쌍 전부 일치 확인). `FREEZE.json`의 `diffpair.py` 해시는 v1 시점 값이다.
