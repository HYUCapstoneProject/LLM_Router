## 4. 구분력 자체는 크게 좋다

| 자기 원질문과의 점수 | 같은 뜻 vs 함정 AUC |

| quora 리랭커 | 0.748 |
| NLI xsmall | 0.876 |
| NLI base | **0.931** |
| 결합(LR) + NLI base | 0.935 |

NLI는 긴 문항에서도 같은 뜻과 함정을 잘 가른다. 문제는 점수가 아니라 기준값이다. 긴 문항은 원문 대부분이 같아 같은 뜻과 함정이
모두 함의 점수가 높게 나오므로, 대화형 데이터에서 고른 기준(0.03 근처)은 너무 낮다.

## 6. 층별 (test, 결합 + NLI base 1위만: 같은 뜻 / 함정)

rb_math 97% / 6% · rb_open 100% / 7% · xrb_numeric 100% / 11% · xrb_mcq 100% / 32% · rb_mcq 99% / 37% · **xrb_open 100% / 71%**

가장 약한 곳은 xrb_open(SQuAD형)이다. 긴 지문은 그대로 두고 질문 한 줄만 바꾼 함정이라, 두 입력의 대부분이 같은 지문이다.

## 7. 해석

1. 재현본은 D2의 성질을 그대로 가졌다(C3 함정 통과 69% 대 72%). 따라서 아래 결론은 D2에도 적용될 가능성이 높다.
2. NLI는 형식과 관계없이 구분력이 높다(대화형 0.73 → 0.93, 긴 문항 0.62 → 0.93, 각각 코사인 대비).
3. 그러나 **기준값 하나를 두 분포에 함께 쓸 수 없다.** 짧은 대화형에서 고른 기준은 긴 문항에서 함정의 30~50%를 통과시키고,
   긴 문항에서 고른 기준(0.99대)을 짧은 질문에 쓰면 같은 뜻 재사용이 크게 줄 것이다.
4. vCache가 지적한 문제와 같다. 실제 적용에는 입력 길이·형식별로 기준을 나누거나, 항목별로 기준을 학습하는 방식이 필요하다.

## 8. 한계

  재현됐다고 본다. 원본 D2로 다시 확인하는 것이 가장 확실하다.
