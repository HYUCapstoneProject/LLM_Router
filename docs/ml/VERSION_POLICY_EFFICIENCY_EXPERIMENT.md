## 1. 이전 실험과의 관계

- **RF-02~04(F1~F5):** 운영 버전 정책은 고정하고 데이터 구성만 바꿨다. 출발 모델이 전체 데이터로 학습한 운영 1.0이라 이미 천장 근처였고(EV-04) 어떤 재학습도 개선을 내지 못했다. 이번에는 **M0를 일부러 덜 학습시켜 개선 여지를 남기고**, 비교 축을 데이터가 아니라 **학습 방식**으로 둔다.
- **F5와의 차이:** "오답 + 라벨 비율 맞춤"은 같지만, 채우는 문항을 같은 window의 맞힌 문항이 아니라 미리 빼 둔 reserve에서 가져온다.
- **RF-05:** 분포가 바뀔 때의 갱신 방식 비교다. RF-06은 같은 분포에서 학습 방식의 비용만 보며 서로 다른 축이다. RF-05 결론의 "본체 재학습은 드물게"에 비용 숫자를 준다.
- **해석 범위:** 초기 데이터가 적어 개선 여지가 있는 시기의 결과다. 현재 운영 1.0 상황으로 그대로 옮기지 않는다.

## 2. 비교군

| Arm | round k의 학습 행 | 시작 가중치 |
|---|---|---|
| P0 동결 | 없음(기준) | M0 |
| **P1 버전 정책** | 현재 cycle의 누적 batch 전부 + 지난 cycle replay(라벨별 stable hash 순 최대 32) + D_seed 복습(라벨별 32) | 마지막 `.0` anchor 가중치(1.x는 M0, 2.x는 2.0, 3.x는 3.0). optimizer·scheduler는 매번 새로 |
| **P2 전체 재학습** | D_seed ∪ B1…Bk 전부 | 매번 M0 |
| (선택) P2-eq | P2와 같은 행, P1의 같은 round step 수에서 멈춤 | M0 |

- P1은 [ML 명세 5.4절](README.md#retraining-4)의 `successfulHttpRequest` 규칙 그대로다. 품질 gate 없이 직접 승격하고, 15번째 성공의 pristine rebase까지는 가지 않는다.
- 모든 arm은 자기 행으로 3 epoch(`routing_objective_continual_v1.json`: lr 2e-5, batch 8×4, warmup .1, 512토큰, ordinal CE)를 돈다. P2의 비용이 커지는 것 자체가 측정 대상이다. sample_weight는 1이다.
- P2-eq는 P1의 이득이 "정책" 때문인지 "덜 학습해서"인지를 나누는 대조다.

## 3. 데이터와 크기 결정

**표(로컬 `plan.py build`):** EV-10 00_prepare 표에서 만든다.

| 표 | 행 | 규칙 |
|---|---:|---|
| pool | 35,017 | EV-10 train. v2 제외 159행 제외, 단계 하나가 빈 444행은 EV-10 03_ours처럼 이웃 단계로 채움 |
| dev | 7,591 | 단계가 빈 행·v2 제외·평가 제외(문서 제공형 80) 뺌. round마다 품질 추적, pilot 선택 |
| test | 17,662 | 같은 규칙(영어 아닌 246·문서 제공형 100 포함 제외). 마지막 round 모델만 평가. EV-10 08에서 이미 열었으므로 설정 변경에 쓰지 않는다 |

중복 묶음은 A 분할 `duplicate_group_id`, 외부 데이터 `split_group_id`(EV-10 재분할 단위)로 둔다. 학습 내부 검증은 dev의 48행(라벨별 16, 운영과 같은 크기)이다.

**크기 규칙(00_pilot, 결과를 보기 전에 고정):** 데이터가 너무 적으면 P2가 당연히 앞서고, 너무 많으면 둘 다 천장에 붙어 차이가 보이지 않는다. 그래서 감으로 정하지 않고 pilot 학습 곡선으로 정한다.

1. pool에서 1k·2k·4k·8k·16k행 표본(원천 비율 유지, 중복 묶음 통째로, 작은 표본은 큰 표본에 포함)으로 각각 3 epoch 학습하고 dev source-macro-F1(원천별 3라벨 macro-F1의 평균)을 잰다.
2. **n0** = "항상 easy" 기준선과 16k 점수 사이 간격의 50% 이상을 닫는 가장 작은 크기. 그 pilot 모델이 M0다.
3. **stream 크기 S** = 16k − n0. 측정한 범위 안에서 끝나므로 외삽하지 않는다. pilot에서 16k와 n0의 차이가 .03(판정 기준의 3배) 미만이면 멈추고 설계를 다시 정한다.
4. **window 크기 W** = S / (9 × b). b는 M0의 dev 예측에 batch 규칙을 적용했을 때 평가 문항 1개당 batch 행 수다. M0가 한쪽 라벨을 주로 틀리면 채움 행이 많이 필요하다. reserve가 그만큼 댈 수 없으면 W를 댈 수 있는 최대(dev 채움 비율 기준, 안전계수 .9)로 줄이고, 줄인 stream의 pilot 곡선 이득(로그 행 수 보간)이 .03 이상인지 다시 확인한다. 미만이면 멈춘다.

**분할:** D_seed = n0 표본, D_probe = 남은 풀에서 9W행(원천 비율 유지, 중복 묶음 통째로, 9 window로 균등 분할), D_reserve = 나머지.

**batch 규칙(round k):** window k에서 고정 로거 M0가 라벨 l로 틀린 수 e_l, 풀 비율 p_l에 대해 N = max_l(e_l / p_l), 목표 t_l = max(e_l, round(N·p_l)). 틀린 문항은 모두 넣고, 모자란 t_l − e_l을 reserve의 라벨 l에서 고정 순서로 채운다(재사용 없음). reserve가 모자라면 봉인 전에 멈춘다. 맞힌 probe 문항은 어느 arm도 학습하지 않는다.

**고정 로거(결정 D1):** 오답은 M0 기준으로 한 번만 정해 두 arm이 같은 batch를 받는다. 학습 방식만 분리하기 위해서이며 RF-02~04와 같다. 각 arm이 자기 모델로 오답을 고르는 on-policy는 범위 밖이다.

## 4. 평가

| 축 | 지표 |
|---|---|
| 품질(주) | round마다 dev source-macro-F1, 마지막 round의 test source-macro-F1 |
| 품질(보조) | window 2~9 prequential(도착 당시 서비스 중인 모델 = 직전 round 모델), 정확도, hard 재현율, 높게·낮게 예측한 비율. 예측 라벨을 시작 단계로 쓴 라우팅: 첫 시도 성공, 최종 해결, 호출 수, 비용(1:3:5), 같은 비용의 고정 시작 선 대비 첫 시도 이득(기술 통계) |
| 계산 | 누적 optimizer step, T4 학습 시간(추론 제외), 처리 샘플·토큰 |
| 효율 | round별 P2/P1 계산 배수, "P2 마지막 dev − .01"에 처음 닿은 round와 그때까지의 계산 |

차이는 질문 그룹 단위 paired bootstrap(2,000회, 원천별 독립 재표집, 원천 평균) 95% 구간으로 낸다. seed가 여럿이면 확률을 seed 평균해 예측한다.

## 5. 가설과 사전 판정

| 가설 | 판정 |
|---|---|
| H0 전제 | P1·P2 모두 test에서 P0보다 +.01 초과, 구간 하한 > 0. 실패하면 학습 자체에 효과가 없는 것이므로 효율 비교를 보류한다 |
| **H1 주** | P1 − P2의 95% 하한 > −.01이면 "비열등". 상한 < −.01이면 "열등". 구간이 −.01에 걸치면 "미확인"이며 seed 43·44를 추가한다(결정 D4, EV-10 4.3 규칙) |
| H2 | 계산 배수는 기준 없이 측정값으로 보고한다(예시 크기 추정 약 4배) |
| H3 기술 | cycle 안 위치(x.1, x.2, x.0)별 P1 − P2 dev 차이, anchor가 이어질수록 차이가 쌓이는지 |

결론은 "품질 손실 없이 계산 X배 절약", "Y 품질 손실과 X배 절약의 교환", "차이 미확인" 중 하나로 쓴다.
