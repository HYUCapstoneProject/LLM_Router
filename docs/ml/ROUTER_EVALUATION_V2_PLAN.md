# 라우터 평가 기준 통일과 v2 최종 실험 계획서

작성일: 2026-10-13. **실행 전 계획**이며 노트북·실행 코드는 9절 결정 후 만든다. 운영 변경 승인이 아니다.

지금까지의 재학습·비교 실험은 지표가 실험마다 달랐다(난이도 라벨 정확도, 첫 시도 품질, 최종 해결률, nAUC). 그래서 "어떤 라우터가 가장 좋은가"를 한 기준으로 답하지 못했다. 이 계획서는 세 가지를 정한다.

1. **모든 라우터에 같은 기준**(해결률·비용·정확도)을 적용하는 평가 방식
2. v1 채점 오류의 영향을 정리하고 **v2로 넘어갈지 결정할 최소 실험**
3. 이미 준비한 **외부 평가 데이터**(LLMRouterBench·SPROUT·RouterArena)의 쓰임

## 2. "가장 좋은 라우터"의 기준

### 2.1. 주 기준: 상향을 포함한 서비스 효용

질문 하나에 대해

```text
U = 최종 해결(0/1) − λ × 총비용 − κ × 실패한 시도 수
```

- **총비용**은 상향을 포함한 모든 호출의 실제 비용이다. 원천마다 "전부 high로 보낼 때"의 평균 비용을 1로 둔다.
- **λ**는 비용의 무게다. λ = .2이면 전부 high로 보내는 비용을 해결률 20%p와 같게 본다.
- **κ**는 첫 답이 틀려 사용자가 다시 요청하는 불편의 무게다. κ = 0이면 끈기 있는 사용자(배치·비대화형), κ가 크면 첫 답이 중요한 대화형 서비스다.
- **판정:** 서비스가 정한 (λ, κ)에서 효용이 가장 높은 정책이 가장 좋은 라우터다. 범위를 정하지 못하면 λ × κ 격자의 효용 지도에서 지배 관계로 보고한다.

이 기준은 지금까지의 지표를 모두 포함한다. κ = 0이면 "최종 해결률 대비 비용", κ가 크면 "첫 시도 품질 대비 비용"으로 수렴한다. 1절에서 본 두 현상(최종 해결은 늦게 시작할수록 떨어지고, 첫 시도는 비싸게 시작할수록 오른다)이 하나의 식 안에서 저울질된다.

### 2.2. 보조 지표 (문헌 지표와의 대응)

| 지표 | 정의 | 대응 문헌 |
|---|---|---|
| 첫 시도 품질–비용 곡선과 혼합선 대비 이득 | 같은 첫 시도 비용에서 고정 단계 혼합선보다 얼마나 높은가 | RouterBench의 Zero router·AIQ |
| oracle 격차 회복률 | (방법 − 혼합선) / (oracle − 혼합선), 같은 비용 | RouteLLM의 PGR·APGR |
| 목표 해결률에 필요한 비용 | always-high 첫 시도 성공의 x%에 도달하는 최소 비용 | RouteLLM의 CPT(x%) |
| 4종 세트 | 첫 시도 성공·최종 해결·평균 호출 수·총비용 | 천장 분석 4절 |

### 2.3. 정확도: 모든 라우터에 같은 정의

- **필요 단계 정확도:** 고른 시작 단계가 "처음부터 풀 수 있는 가장 싼 단계"와 같은 비율, 그리고 너무 낮게·너무 높게 고른 비율이다. 모든 라우터가 시작 단계를 내므로 R0~R3·논문 라우터·고정 정책에 똑같이 적용된다.
- **난이도 라벨 일치**(T1, RouterArena 공식 라벨)는 R0처럼 난이도를 직접 내는 라우터의 **진단 지표로만** 쓴다. R1~R3는 난이도 분류기가 아니므로 순위 근거로 쓰지 않는다.

### 2.4. 일반화·견고성과 통계 규칙

- 원천별로 따로 보고하고, 외부 데이터(E3)와 RouterArena 변형 쌍(412쌍)의 선택 일관성을 함께 본다.
- 보정·정책 선택은 calibration 분할(D_dev 또는 외부 데이터의 calibration 30%)에서만 하고 test는 한 번만 쓴다.
- 차이는 질문 그룹 단위 paired bootstrap 95% 구간으로 보고한다. 평가는 v2 채점을 기준으로 하고 v1 값을 함께 적는다.

## 3. 모든 라우터에 같은 기준을 적용하는 방법

### 3.1. 공통 출력으로 바꾸는 어댑터

라우터마다 출력의 뜻이 달라 같은 λ가 같은 비용 조건을 뜻하지 않았다(README 3.6절). 그래서 모든 라우터의 출력을 calibration 분할에서 **단계별 성공 확률 p̂ₜ(x)**로 바꾼 뒤 같은 결정 규칙을 쓴다.

| 라우터 | 원래 출력 | 어댑터 |
|---|---|---|
| R0 | 난이도 확률 | train의 "라벨별 단계 성공률" 표를 곱해 단계별 성공 확률로 바꾼 뒤 단계별 isotonic 보정 |
| R0-τ | 같음 | 누적 확률 문턱(비교용으로 유지) |
| R1 | 단계별 성공 logit | sigmoid 후 단계별 isotonic 보정 |
| R2 | 단계 간 상대 우열 logit | 단계별 isotonic 보정(점수 → 성공) |
| R3 | 비용을 반영한 효용 logit | 단계별 isotonic 보정. 학습에 쓴 λ를 기록한다 |
| kNN 효용 라우터 등 논문 라우터 | 성공 추정치나 점수 | 단계별 isotonic 보정 |
| 고정 시작 정책·oracle | – | 상수 / 사후 정답 |

### 3.2. 공통 결정 규칙

1. **한 번에 고르기:** argmaxₜ [p̂ₜ − λ ĉₜ]. 기존 R1·R2 정책과 같다.
2. **상향을 고려한 시작 단계(새 방식):** 시작 단계 s마다 기대 최종 해결, 기대 총비용, 기대 실패 횟수를 p̂와 단계 간 실패 상관 ρ로 계산한다. ρ는 calibration 분할에서 추정한다. 그다음 효용 U가 가장 큰 s를 고른다.
   - 가장 가까운 선행 연구는 [cascade routing](https://proceedings.mlr.press/v267/dekoninck25a.html)(Dekoninck et al., ICML 2025)이다. 라우팅과 cascade를 하나의 최적화로 묶는다는 점이 같다.
   - 차이도 있다. 우리 서비스는 답을 만든 뒤 품질 추정기로 다음 단계를 정하지 않는다. 사용자가 불만족할 때 정해진 순서로 올라간다. 그래서 "어디서 시작할지"만 정하고, 상향 여부는 실제 실패로 결정되는 구조에 맞췄다. κ로 사용자 불편을 명시하는 점도 다르다.

### 3.3. 시제품 결과 (재학습·추론 없음)

R0·R1의 기존 test 점수에 어댑터를 붙였다. 보정은 D_dev, 평가는 봉인 test이고 둘 다 v2 채점이다. 표는 λ = .2일 때의 효용이다. 상세는 [시제품 결과](../../experiments/results/unified-eval-prototype-20261013/README.md)에 있다.

| RouterBench | κ = 0 | κ = .15 | κ = .4 |
|---|---:|---:|---:|
| oracle | .888 | .859 | .810 |
| R0 + 어댑터, 상향 고려 | .885 | **.808** | **.728** |
| R1 + 어댑터, 상향 고려 | .885 | .807 | .727 |
| medium부터 시작 | .856 | **.808** | .727 |
| low부터 시작 | **.885** | .774 | .590 |
| 운영 R0 (argmax) | .863 | .786 | .659 |
| R1 + 어댑터, 한 번에 고르기 | .809 | .778 | .726 |

| xRouteBench | κ = 0 | κ = .15 | κ = .4 |
|---|---:|---:|---:|
| oracle | .818 | .765 | .678 |
| R0 + 어댑터, 상향 고려 | .815 | **.740** | .663 |
| R1 + 어댑터, 상향 고려 | .815 | **.740** | **.664** |
| medium부터 시작 | .791 | .739 | .652 |
| low부터 시작 | **.815** | .726 | .579 |
| 운영 R0 (argmax) | .796 | .737 | .639 |

- **어댑터를 거치면 R0와 R1이 같은 효용을 낸다.** 난이도 분류기도 보정하면 성공 예측기와 같은 정보를 준다. R0만의 약점은 학습 목표가 아니라 고정 연결 규칙이었다.
- **상향을 고려한 규칙은 각 κ에서 가장 좋은 고정 시작 단계와 같거나 조금 낫다**(xRouteBench κ = .4에서 +.011). 반면 κ를 모르는 "한 번에 고르기"는 비용을 과하게 써서, κ ≤ .15에서 고정 정책보다 못하다.
- 운영 R0(argmax)는 "medium부터 시작"보다 RouterBench에서는 κ > 0 전 구간, xRouteBench에서는 κ ≥ .15에서 낮다.
- **이 데이터에서는 "κ에 맞는 시작 단계 고르기"가 효용의 거의 전부이고, 질문별 라우팅의 추가 가치는 작다.** 이 결론이 새 세대 모델과 서비스형 질문에서도 유지되는지가 E3의 핵심 질문이다.

### 3.4. R3와 분할

R3는 G1 분할(train 18,591)로만 학습돼 있어 A 분할과 섞지 않는다. G1 분할 안에서 R1과 R3를 같은 어댑터로 비교한다. G1 selection·holdout 점수 파일이 필요하다(9절 결정 4).

## 4. 추가 평가 데이터의 쓰임

| 데이터 | 가진 것 | 이 계획에서의 역할 | 주의 |
|---|---|---|---|
| **LLMRouterBench** (2025년 모델 13개, Claude Sonnet 4 포함) | 문항별 정답·비용. calibration 30% / test 70% | **E3 주 무대.** calibration에서 Haiku·Sonnet·Opus와 가격 비율이 비슷한 세 단계를 고르고, 각 라우터 점수를 어댑터로 새 단계에 소량 보정한 뒤 test에서 효용을 비교한다. Claude로 옮길 때의 대리 실험이다 | 어려운 과제 위주(HLE·SimpleQA). 원천 자체 채점 |
| **SPROUT** (2024년 모델 13개, Claude 3.5 Sonnet·GPT-4o·4o-mini) | 문항별 판정 점수와 출력 토큰. 일반 대화 19,117문항 | 서비스형 질문에서 "싼 단계로 충분한 비율"과 라우터의 추가 가치 확인 | 달러 비용이 없어 공개 가격 × 토큰으로 계산(9절 결정 3). LLM 판정 채점 |
| **RouterArena** (8,379) | 공식 난이도 라벨과 정답만. 모델 응답 기록 없음 | 라벨 일치 진단(기존). 외부 데이터와 같은 문항 700개(LLMRouterBench 663 = MMLU-Pro 646 + AIME 17, SPROUT 38)는 기록을 재사용해 해결률을 잰다 | 700문항은 MMLU-Pro 위주라 전체 분포와 다르다(hard 15% vs 23%) |

- 외부 데이터는 학습에 쓰지 않는다. calibration 분할은 어댑터 보정과 정책 선택에만, test는 한 번만 쓴다(외부 평가 데이터 문서 6절).
- **RouterArena 해결률을 재는 방법은 세 가지뿐이다.** 공식 평가도 라우터가 고른 모델을 실제로 호출한 답을 채점하며([RouterArena](https://github.com/RouteWorks/RouterArena)), 후보 모델 응답을 미리 공개하지 않는다.
  1. 위 700문항 부분집합(비용 0)
  2. 층화 표본을 실제 서비스 후보로 호출하는 E4
  3. 공식 파이프라인으로 전체 실측(비용 대비 정보가 적어 권하지 않음)

## 5. v1 채점 오류의 영향 (재학습 없이 측정)

| 항목 | 영향 |
|---|---|
| 난이도 라벨 | 20%가 바뀐다(v2 최종). 정정 자체의 효과는 8.4%(같은 경계 .27/.64)이고, 나머지는 경계 재선택(.36/.73) 때문이다. GSM8K는 같은 경계에서도 35%가 바뀐다 |
| 라벨 비율 (easy/medium/hard) | v1 50/37/13% → v2 같은 경계 57/33/10% → v2 최종 46/39/15% |
| R1 학습 정답 (대표 3모델 칸) | RouterBench 4.6%(2,565칸 중 2,365칸이 실패→성공), xRouteBench 7.8% |
| test 해결률 | 모든 방식 +2~6%p. high만 82.4% → 88.8%(RouterBench) |
| 방법 간 순위 | Kendall τ: 첫 시도 1.0, 최종 해결 .93~1.0 |
| R0 라벨 정확도 (test) | v1 라벨 .619, v2 같은 경계 .623, v2 최종 .576 |

**결론:** 평가의 순위 결론은 v1 오류에 강건하다. 바뀌는 것은 절대 수치와 라벨 비율이다. 학습된 라우터에 미친 영향은 재학습 없이는 알 수 없으므로 E1 한 번으로 확인한다.

## 6. 필수 실험

### E1. v2 재학습 대조 — "v1 오류가 학습된 라우터를 나쁘게 만들었나"

| 항목 | 내용 |
|---|---|
| 대상 | R0(CE)와 R1(BCE) 두 개만 |
| 데이터 | **같은 A 분할 행**에 v2 정정만 적용하고 제외 문항(RouterBench 290)을 뺀다. 행과 분할을 바꾸지 않아야 채점 정정의 효과만 분리된다. R0 경계는 .27/.64 유지(9절 결정 2) |
| 학습 | 기존과 같은 ModernBERT-base, seed 42, 512 학습, 같은 step 예산 |
| 평가 | v2 test에서 2절 기준(효용 지도, 4종 세트, 필요 단계 정확도). v1 학습본과 v2 학습본의 paired bootstrap. E3에도 같이 넣는다 |
| 판정 | v2 학습본이 κ ∈ {0, .15}, λ = .2에서 효용 +.01 초과(구간이 0을 포함하지 않음)면 v2를 학습 기준으로 전환한다. 아니면 "v1 오류는 학습된 라우터의 성능에 실질적 영향이 없음"으로 기록하고, v2는 평가 기준으로만 쓴다 |
| 자원 | T4 학습 2회(각 약 1시간)와 test·외부 추론 |

### E2. 통일 기준 재평가 — "어댑터를 거친 뒤 어떤 라우터가 어떤 κ에서 최선인가" (학습 없음)

| 항목 | 내용 |
|---|---|
| 대상 | A 분할: R0, R0-τ, R1, R2(기존 점수), 고정 시작 정책 3개, oracle. G1 분할: R1, R3. 강한 단순 기준선으로 kNN 효용 라우터 1개(BGE 임베딩, CPU) |
| 방법 | 3절 어댑터와 두 결정 규칙, 2절 지표. 보정·선택은 D_dev, 평가는 v2 test |
| 판정 | 라우터 채택 조건은 "목표 κ에서 가장 좋은 고정 시작 정책보다 효용이 +.01 초과(구간 0 미포함)"다. 만족하는 라우터가 없으면 "라우터 없이 κ에 맞는 시작 단계 정책"을 권고한다 |
| 자원 | CPU. R2·R3 점수 파일 확보(GCS·Drive 읽기) |

### E3. 외부·세대 전이 — "옛 데이터로 배운 라우터가 새 세대 모델과 서비스형 질문에서도 쓸모 있나" (추론만)

| 항목 | 내용 |
|---|---|
| 대상 | E1의 R0·R1(v1 학습본과 v2 학습본), 고정 시작 정책, kNN |
| 데이터 | LLMRouterBench 주 평가(7,674), SPROUT 일반 대화(19,117), RouterArena 700 부분집합 |
| 방법 | 라우터 추론(8192, T4 약 30~40분). calibration 30%에서 세 단계 선택·어댑터 보정·정책 선택, test 70%에서 한 번 평가 |
| 판정 | E2와 같은 규칙. 추가로 "단계별 성공을 얼마나 잘 줄 세우는가"(AUROC)를 세대 간 전이 지표로 보고한다 |

### E4 (선택). RouterArena 해결률 실측

층화 표본 약 1,000문항(원천 × 난이도)을 서비스 후보 세 단계로 호출하고, RouterArena 공식 채점 규칙으로 맞음·틀림을 기록한다. 비용은 수십 달러 규모로 추정한다(질문당 입력 200·출력 500토큰, 이전 세대 공개 가격 기준이며 현재 가격 확인 필요). E3 결과를 본 뒤 결정한다.

## 7. 하지 않는 것과 이유

| 하지 않는 것 | 이유 |
|---|---|
| F1~F5의 v2 재실행 | 재학습이 초기 R0를 못 넘은 원인이 라벨 비율과 텍스트 정보의 한계로 설명됐다. v1 오류는 방법 간 순위를 바꾸지 않았다 |
| R2·R3의 v2 재학습 | 기존 점수로 E2에서 비교할 수 있다. R1과의 차이도 작다 |
| 논문 라우터 6종 전체 구현 | 문헌의 정체 현상과 우리 천장 분석상 차이가 작을 것이다. kNN 하나로 "강한 단순 기준선"만 확인한다 |
| 512/8192 재비교, 표현 비교 재실행 | 결론에 영향이 없다 |
| 일상적 seed 반복 | E1 결과가 판정 경계(±.01) 근처일 때만 seed 17·73을 추가한다 |
| RouterArena 전체 실측 | 비용 대비 정보가 적다. 부분집합과 표본으로 충분하다 |

## 8. 순서

1. **E2**(CPU, 점수 파일 확보) — 평가 코드와 어댑터를 먼저 고정한다
2. **E1**(T4 학습 2회) — 같은 평가 코드로 v1 학습본과 v2 학습본을 비교한다
3. **E3**(T4 추론 1회 + CPU)
4. 보고서 작성. E4는 E3 결과를 보고 결정한다

## 9. 결정 항목

| # | 결정 | 선택지 | 권장 |
|---|---|---|---|
| 1 | 판정에 쓸 (λ, κ) | 격자만 보고 / 대표점 지정 | 격자(λ .05·.2·.5, κ 0·.05·.15·.4)를 보고하고, 판정은 λ = .2, κ ∈ {0, .15} |
| 2 | E1의 R0 경계 | .27/.64 유지 / v2 재선택 .36/.73 | 유지. 정정 효과만 분리되고, 어댑터가 경계의 영향을 흡수한다 |
